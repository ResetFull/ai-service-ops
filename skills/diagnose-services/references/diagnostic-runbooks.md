# 有界诊断手册

先定义现象、准确服务/节点、故障墙上时间和服务器时区。task diagnose 负责采证；最终推理须列出事实、假设、反证、缺口和下一步，不能由关键词数量直接宣布根因。

## 启动失败

自动收集指定服务 status、节点 net、jvm 服务过滤和 logsrange；未指定时间则采 health，并标注历史覆盖不足。

| 假设 | 支持证据 | 需要反证或补证 |
|---|---|---|
| 进程未启动或退出 | 精确服务进程缺失，启动窗口有退出/异常 | status 是当前快照；无进程不能说明为何退出 |
| 端口冲突 | 启动窗口 BindException 与监听占用对应 | 必须核对预期端口与占用者；未配置端口时不能猜 |
| 依赖或配置失败 | 同次启动中明确的连接、鉴权或配置异常 | 后续重试成功、其他节点成功、配置版本证据 |
| 主机资源不足 | 同时段 OOM/磁盘满等明确错误 | 当前 mem/disk 采样不能证明历史资源状态 |

有进程、有监听都不单独证明就绪。缺配置的 HTTP 探测不自行补端口；heap/线程/GC 需独立可用工具和只读授权范围。没有充分证据时输出 UNDETERMINED。

## HTTP 502

先确认请求入口、发生时间、目标服务和**明确的 Nginx 节点**。自动采集服务/监听/日志，再在指定节点读取 nginx-config 与 nginx-stats。未给代理节点时不遍历或猜测。

| 假设 | 支持证据 | 需要反证或补证 |
|---|---|---|
| upstream 连接被拒绝 | 同窗口 Nginx connect failed、对应上游无监听 | 当前监听恢复不能排除短时退出 |
| 上游重置/提前关闭 | Nginx upstream closed/reset 与服务异常时间对应 | 区分客户端取消、代理链和服务主动断开 |
| 路由或配置不一致 | 目标 upstream 与预期服务/端口不符 | 磁盘配置不证明已加载；include/变量可能未覆盖 |
| 资源或依赖导致异常 | 服务同窗口异常与依赖/资源证据对应 | 延迟/关键词并非充分因果证据；区分 502 与 504 |

nginx-stats 默认采样范围不等于故障时间范围；需核对实际日期、文件与时间，必要时用受支持的有界查询补充错误日志。没有 access/error 同窗口对应证据时，不把当前进程正常写成历史 502 已解释。

## 停止与交付

SSH/认证失败立即停止，不循环尝试。达到文件、字节、时间或输出预算标为 PARTIAL；缩小窗口或指定节点后再补充。无匹配记 NO_MATCH，无日志记 NO_LOG，均不能推断没有故障。只读诊断不自动重启、修改配置或回滚。

报告结构：现象与范围 → 已验证事实及 job-id/采样时间 → 候选原因及反证 → 尚缺证据 → 最小下一步。只在证据足够时给出已定位原因。
