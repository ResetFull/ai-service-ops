# Operate Test Services

操作已配置的测试服务，确保源码、构建产物、发布目标和验证结果可以对应。prod 变更走正式生产运维流程。

公开版默认只读。非生产写操作还需用户在外部 settings.json 中显式设置 write_enabled=true；
该设置不扩大当前任务授权。不要通过改配置、改请求标识或旧入口绕过禁用策略。

完整分组为 `domestic-test` 或 `overseas-test`；旧 `test` 兼容国内。`domestic-dev`、`overseas-dev` 仅承接明确指定节点与命令，不复用测试构建 profile 自动发布。两个生产分组不承接写操作。先核对 [资产与认证](../diagnose-services/references/topology.md)，缺地址/认证/发布配置时停止，不借国内同名节点替代海外节点。

## 入口与授权

以当前文件为基准解析 `../../scripts/service-ops.ps1` 或 `../../scripts/service-ops.sh` 的绝对路径。命令、配置、发布记录和失败恢复规则见 [operations.md](references/operations.md)。

当前任务已明确授权的目标和动作持续有效，不逐轮重复索要授权。“检查、排查、预检”只授权查询；“发布、部署”授权目标服务的完整发布链路；“构建、上传、重启、回滚、执行命令”只授权对应动作。环境/目标有歧义、扩大动作范围或涉及首次目录布局迁移时先确认。

非生产目标已授权后直接执行，不因工作区未提交或常规发布步骤追加确认。仍记录源码状态和指纹，验证构建前后及上传时的一致性；不得以此扩大目标、删除数据或绕过生产只读限制。

不直接拼 SSH/SCP/Maven 绕过脚本，也不借 `exec` 绕过发布条件。自定义命令须由用户明确给出测试节点和命令；删除数据、清空目录、改防火墙等难恢复动作还须先只读确认准确目标。

## 发布与验收

1. 运行 `test doctor deploy` 和 `test <service> plan`，核对仓库绝对路径、分支/SHA、工作区状态、构建类型、产物、目标节点及验证 URL。
2. 按授权执行对应动作。完整发布必须在写操作前确认就绪 URL 和远端发布布局；缺配置不猜测，首次静态目录迁移单独处理。
3. `build` 核对构建前后源码身份，生成固定的发布记录和产物快照；`all` 持续使用自身的记录，`upload` 再次核对源码身份与产物 SHA-256。锁冲突或依赖安装失败时停止，不临时改包管理器或绕过锁文件。
4. `verify` 核对远端产物身份、后端进程和已配置就绪探测；前端还须核对通过 HTTP 返回的 releaseId。缺测记为未知，HTTP 200 和进程存在不能单独证明版本正确。

阶段失败立即停止后续写动作，保留已完成阶段和当前状态。回滚仅在授权后执行，恢复指定版本并验证；不默认把发布授权扩展成回滚或目录迁移授权。

Python 3.10+ 可用时，授权操作优先用 `task --request-id <本次操作唯一标识> run test <service> <action>` 保存任务/阶段回执；完整发布仍用单个 all。详见 [任务回执](../diagnose-services/references/tasks.md)。旧入口保留。

SSH/SCP 超时、被中断或连接断开时，写操作按 UNKNOWN 处理，保留远端锁；查询超时仍为 PARTIAL。不得自动换 request-id 重放、删除锁或回滚。先 `task reconcile <job-id>` 只读收集发布身份与固定版本验证证据，人工核对操作是否仍在运行及锁归属后，再按已有授权范围决定下一步。现有观察不能证明远端进程已终止时继续保留 UNKNOWN。

## 交付

报告服务、节点、源码 SHA、releaseId、产物哈希、各阶段结果和验证范围。区分“产物已切换”“进程已启动”“就绪检查通过”，明确失败后的现状、可恢复版本和需要用户处理的配置/网络条件。不要把编译通过写成服务验收通过。
